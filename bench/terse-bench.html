Measurement instrument · spec v0.3.1 · pre-registered

TERSE Bench

Does the notation keep its promise? This instrument measures tokens saved against comprehension kept, prose vs TERSE, on the same documents and the same questions. Success criterion, fixed in advance: ≥ 50% fewer tokens with ≤ 2 pts QA accuracy loss.

00

Endpoint

Inside a claude.ai artifact, keep "Claude artifact" — no key needed, usage counts against your Claude plan. Anywhere else (this file opened locally in a browser), pick a provider and paste an API key: the key lives in this page's memory only, is never stored, and is sent only to the provider you selected. Local models: choose "OpenAI-compatible" with base URL http://localhost:11434/v1 (Ollama) and any non-empty key — runs are then free.

01

Corpus builder

Paste a prose document; the builder converts it to TERSE (with a mandatory self-check pass), audits the two versions for information equivalence, then writes QA pairs from the prose only — including one trap question whose gold answer is "not in context". Review and edit the JSON before adding: you are the editor, the model is the typist. Uses the endpoint above (~3 requests per document). In artifact mode the output is capped — for documents longer than ~600 words, use an API or local endpoint.

02

Corpus

Each document exists in two versions (prose and TERSE) with gold-answer questions written before any run. Edit the JSON directly, or export it, work outside, and load it back. The sample corpus ships with 3 documents (EN + FR).

03

Protocol

Arms of the run. Token counts come from the API's own usage field with an identical wrapper for every version — absolute counts include a small fixed overhead, so the deltas are exact. When the question count is below a document's available questions, that many are drawn at random without replacement; the same draw serves every arm of that document, so arms stay comparable within a run (different runs draw differently — use "all" for fully reproducible runs).

Run matrix — one row per document, one column per version. Tick the cells to measure; a header checkbox toggles its whole column, the corner box toggles everything. The same question draw serves every ticked version of a row, so versions stay comparable.

In artifact mode, every request counts against your Claude plan; in API modes it bills the provider key; on a local model it is free. To scale a run down: quick mode (4 questions), fewer documents, one arm at a time, or a small reader. The reader model is a benchmark variable in its own right — a notation that only works with large readers would be a weak notation.

04

Run & results

Idle. Budget ≈ ticked cells × (questions × 2 + 1) requests — scale with the matrix, quick mode, or a small reader.
