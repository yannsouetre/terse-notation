# Reasoning in a condensed medium — exploratory annex

*Companion experiment to TERSE. Status: exploratory — one problem class, one run per
configuration, two model families, two languages. It does not modify TERSE v1 claims.*

## Question

TERSE v1 measures notation as an **input** format. This annex asks the symmetric question:
what happens when the notation is the **medium of the reasoning itself** — when a model must
produce its entire chain of thought in full prose, in telegraphic "short", or in TERSE, where
the inference connectives survive as operators (`->` therefore, `=>` if-then, `x` eliminated
with reason, `?` open hypothesis, `!` intermediate conclusion)?

Pre-registered hypothesis (written before the first run): *TERSE ≈ prose accuracy at ≈ short
token cost, because the markers keep the inferential glue that short deletes.* Verdict below —
partially supported, and the strongest finding is one we did not predict.

## Protocol

24 constraint-satisfaction puzzles (5 people × 3 attributes), generated by reverse engineering
from a random solution: constraints sampled until the solution is provably unique (exhaustive
solver, independently re-verified), then minimized, plus 2 true-but-redundant distractors.
At most one direct fact per puzzle; 4–8 conditional / disjunctive / exactly-one constraints
force case-splitting. Required answer: the **full 15-cell grid** (guessing probability ~0),
graded deterministically cell by cell. One independent API call per (problem × style);
per-line style-compliance scoring; 6,000-token cap (no truncation occurred in any run below).
Readers are **non-hidden-reasoning** models only: the visible chain must be the computation.

The **primary dataset is English** (paired instances: same seed, same solutions, same
constraint graphs as the French set). The French runs are kept as a language replication.

Failure anatomy (GPT-5.5): short's four failures include **two total collapses (0/15)** and a
5/15; TERSE's two failures are both 13/15. Same signature as in French (below): when short

## Findings

1. **Capability convergence.** For strong models with a generous budget, the medium does not
   change what gets solved — with one exception, which is the headline:
2. **Short is brittle; TERSE is not.** In two of the four 24-problem runs — both GPT-5.5 —
   marker-free telegraphic reasoning produced total collapses (0/15 grids), and it died twice
   by truncation in the earlier 12-problem run; both Sonnet runs are clean for short. TERSE
   never collapsed to a near-zero grid in any 24-problem run (worst failure: 11/15); its only
   budget death is H07 in the 12-problem run at the 3,500 cap. Markers appear to act as branch
   bookkeeping: `x` keeps eliminations traceable, `?` keeps open hypotheses listed.
3. **Costs are real but family-dependent.** TERSE spends 78–91% of prose's tokens (short:
   59–97%). GPT-5.5 chains are notation-pure (99% compliance); Sonnet drifts telegraphic even
   when asked for prose (55%* — the compliance metric counts function-word lines; enumerations
   lower it).
4. **Prose is not dominated.** GPT-5.5's prose is the only 24/24 in both languages. The
   original hypothesis is supported at Sonnet (condensed media match or beat prose at lower
   cost) and only partially at GPT-5.5 (TERSE sits between short's economy and prose's
   reliability).
5. **Language changes the cost structure, not the reliability ranking.** Solve rates track
   the model family, but the cost ordering flips at Sonnet: in French, short is the cheapest
   medium (80% of prose) and TERSE costs 89%; in English, TERSE is the cheapest (91%) and
   short's economy nearly vanishes (97%). Compliance explains it: asked for "short", Sonnet's
   English chains score 56% against 70% in French — the model largely wrote prose under a
   telegraphic instruction. TERSE holds 84% and keeps its economy in both languages. **The
   notation enforces a condensation discipline that a plain instruction does not** — an effect
   visible only because the protocol was replayed in a second language.

## Instrument postmortem (why the first grading was wrong)

The initial grader matched each person to their answer line by substring. In four puzzles a
participant named *Mara* coexists with a project named *Amarante*: searching "mara" hit
Marek's line (`project=A-MARA-nte`) first, grading Mara against someone else's answers —
exactly 3 cells lost, in every affected run of every family. A hostile audit (run by a second
Claude instance during pre-publication review) caught it; the buggy grader was shown to
reproduce 215/215 stored values, the anchored fix was stress-tested (perfect grid → 15/15 on
all 24; one wrong cell → 14/15; line order irrelevant), and all runs were regraded — original
values are preserved in `*_original` fields of the regraded files. The earlier "flagged
items" (a cross-family convergence on the same wrong cells) was the bug's signature, not an
under-constrained puzzle: instance uniqueness was re-verified with an independent solver.
Lesson kept: **the instrument is the first suspect.**

## Caveats

One problem class (CSP), one run per configuration, n=24 per run, deterministic grading of a
constrained answer format. This annex claims a pattern, not a theorem.

## Replicate

Open `terse-reasonbench.html` (English) or `terse-reasonbench-fr.html` locally (file://),
pick provider + key — the model list is fetched from your own account and hidden-reasoning
models are flagged — press "Test the endpoint", then Run (72 calls). Problems,
solver-verified solutions, style prompts, compliance scoring and the survival table are
built in.

## Roadmap

Other problem classes (planning, multi-step arithmetic), repeated runs for variance, more
families, and the v2 bridge: semantic LOD applied to reasoning traces (reload only the `!`
skeleton of a previous chain).
